# Рубрика Радара: сводка дня и разбор

Все пункты бинарные. Датасет — снимки дней в `evals/days/ГГГГ-ММ-ДД.json` (входы: изменения, новости, котировки, контекст дня; выходы: текст сводки, разбор). Снимок пишет сам `radar.daily` при каждом выпуске.

## Сводка дня

| # | Пункт | Кто | Что именно |
|---|---|---|---|
| d1 | Самопроверка `digest.check` пуста | код | ссылки есть, нет «конкурент», нет своего банка (own), нет обрывов цитат |
| d2 | Стиль `style.check` без жёстких замечаний | код | запрещённые слова и штампы; длину предложений не считаем |
| d3 | Каждая строка закончена | код | строка в разделах «Условия у банков»/«Новости» заканчивается знаком препинания и не обрывается посреди слова |
| d4 | Каждая строка по банку со ссылкой | код | `<a href` в каждой строке раздела «Условия у банков» |
| d5 | Числа только из данных | код | все числа в строке по банку встречаются в старом/новом значении этого изменения |
| d6 | Не палит автора | код | нет «конкурент», «наш банк», «у нас», «Озон», «Ozon» |
| d7 | Одно событие на строку | судья | строка не склеивает два разных изменения |
| d8 | Понятно, что изменилось | судья | из строки ясно: что было, что стало, или что появилось/убрано; не «страница обновлена» |
| d9 | Читается как факт, не как реклама | судья | нет оценок «выгодно», «удобно», нет маркетинговых оборотов из витрины |

## Разбор (если в этот день был)

| # | Пункт | Кто | Что именно |
|---|---|---|---|
| e1 | Заголовок это вывод | судья | не тема («Т-Банк обновил кредитку»), а утверждение с содержанием |
| e2 | Гипотезы помечены | судья | мотивы банка, прогнозы и «скорее всего» обозначены как гипотеза/оценка, не как факт |
| e3 | Нет причинности из одной точки | судья | нет «X вырос, потому что Y» на одном месяце/одном наблюдении без оговорки |
| e4 | Числа из данных дня | код + судья | каждое число в тексте есть в контексте дня или получено расчётом, который показан |
| e5 | Стиль чистый | код | `style.check` без жёстких замечаний |

## Текст для судьи (сводка)

Ты проверяешь строки ежедневной сводки Telegram-канала о розничном кредитовании. Для каждой строки даны исходные данные: банк, продукт, параметр, старое и новое значение с сайта. Оцени каждую строку, строго 0 или 1:
d7 — 1, если в строке одно событие (одно изменение у одного банка), а не два склеенных. Строка вида «страница условий переписана (N правок). Что изменилось: параметр: было…, стало…; параметр: …» — это ОДНО событие (переписанная страница), перечисление параметров через точку с запятой допустимо.
d8 — 1, если из строки понятно, что именно изменилось: что было и что стало, или что появилось, или что убрано. «Страница обновлена», «условия изменились» без сути = 0.
d9 — 1, если строка написана как факт: без оценок («выгодно», «удобно», «щедро»), без маркетинговых оборотов, скопированных с сайта банка.
Верни ТОЛЬКО JSON: {"lines": [{"i": номер строки, "d7": 0|1, "d8": 0|1, "d9": 0|1, "why": "коротко, только если есть 0"}]}

## Текст для судьи (разбор)

Ты проверяешь аналитический разбор для Telegram-канала, который читают топ-менеджеры банков. Тебе дан текст разбора и, если есть, данные дня, на которых он построен. Оцени строго 0 или 1:
e1 — 1, если заголовок это вывод (утверждение, которое можно оспорить), а не тема или пересказ новости.
e2 — 1, если предположения о мотивах банка, прогнозы и оценки помечены как гипотеза, оценка или «вероятно», а не поданы как факт.
e3 — 1, если нет утверждений о причине по одному наблюдению или одному месяцу («вырос, потому что…») без оговорки.
e4 — 1, если каждое число в тексте либо есть в данных дня, либо получено расчётом, который показан в тексте. Если данные дня не даны, оцени только показанность расчётов.
Верни ТОЛЬКО JSON: {"e1": 0|1, "e2": 0|1, "e3": 0|1, "e4": 0|1, "why": "коротко, только если есть 0"}
